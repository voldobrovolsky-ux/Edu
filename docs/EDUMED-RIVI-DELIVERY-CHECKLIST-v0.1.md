# EDUMED v0.1: RIVI DELIVERY CHECKLIST

## 1. Принцип этапности

Развитие `Rivi` должно идти как расширение уже существующей экосистемы EDUMED и имеющегося модуля Rivi, без пересборки базовой архитектуры ролей, документов, чатов и layout-механики.

## 2. MVP

Цель этапа: дать пользователю работающий визуальный режим с базовыми объектами и понятным входом.

### 2.1. Галерея пространств

- Есть раздел `Rivi` в навигации.
- Открывается список пространств в виде карточек.
- Можно открыть существующее пространство.
- Можно создать новое пространство.
- Есть базовый статус пространства.

### 2.2. Базовое поле

- Пространство открывается на отдельном рабочем поле.
- Основной интерфейс EDUMED визуально сворачивается в компактный элемент возврата.
- Поле поддерживает pan.
- Поле поддерживает zoom с ограничениями.
- Есть лёгкий фоновый паттерн для ориентации.

### 2.3. Базовые объекты

- Текстовый блок.
- Простая фигура.
- Линия/стрелка.
- Карточка документа из EDUMED.

### 2.4. Базовые действия

- Перемещение объекта.
- Изменение размера объекта.
- Удаление объекта.
- Дублирование объекта.
- Выделение одного объекта.

### 2.5. Инструментальная панель

- Плавающая панель отображается поверх поля.
- Есть минимум инструментов: выбор, текст, фигуры, связь, документ.

### 2.6. Сохранение

- Сохраняются положение объектов.
- Сохраняются масштаб и позиция поля.
- При возврате пользователь видит пространство в последнем состоянии.

## 3. V1

Цель этапа: сделать Rivi полноценной рабочей средой для проектной карты и совместной навигации по сущностям EDUMED.

### 3.1. Расширенные инструменты

- Свободное рисование.
- Ластик.
- Несколько цветов и толщин.
- Подписи на связях.
- Редактирование формы связи.

### 3.2. Кластеры и групповые операции

- Множественное выделение.
- Создание кластера из нескольких объектов.
- Имя, цвет и тег кластера.
- Сворачивание и разворачивание кластера.
- Массовое перемещение группы объектов.

### 3.3. Настройка панели инструментов

- Пользователь может скрывать инструменты.
- Пользователь может менять порядок инструментов.
- Конфигурация панели сохраняется между сессиями.

### 3.4. Интеграция с Communitoria

- В группах есть действие `Добавить в пространство Rivi`.
- Можно привязать группу к одному или нескольким пространствам.
- На поле отображается объект группы/чата.
- Чат открывается в режиме `20/80`.

### 3.5. UX-усиления

- Undo/redo.
- Пустые состояния и подсказки для первого входа.
- Подтверждение удаления кластера или важного объекта.
- Блокировка объекта от случайного перемещения.
- Режим `только просмотр`.

## 4. V2

Цель этапа: повысить масштабируемость, обзор больших пространств и удобство интенсивного использования.

### 4.1. Обзор и навигация

- Миникарта пространства.
- Быстрый поиск по объектам на поле.
- Переход к объекту из поиска.
- Список недавно открытых пространств.

### 4.2. Организация содержимого

- Слои и порядок наложения объектов.
- Шаблоны пространств.
- Быстрое создание типовых кластеров.
- Копирование набора объектов между пространствами при наличии прав.

### 4.3. Расширение интеграций

- Богатый предпросмотр документов.
- Глубокие переходы в связанные сущности EDUMED.
- Контекстные действия по документу или группе прямо из объекта.

### 4.4. Надёжность UX

- Устойчивое поведение при потере сети.
- Явная индикация проблем автосохранения.
- Восстановление последней локальной сессии при сбое.

## 5. Что не входит в MVP

Чтобы не перегружать первый этап, в `MVP` не обязательно включать:

- миникарту;
- сложные шаблоны пространств;
- глубокую кастомизацию панели;
- продвинутую работу со слоями;
- расширенные сценарии совместного редактирования;
- сложные настройки групп Communitoria изнутри Rivi.

## 6. Условие архитектурной совместимости

Каждый этап должен проверяться на соответствие текущим принципам EDUMED:

- не создаёт новую автономную систему ролей;
- не дублирует раздел `Документы`;
- не дублирует раздел `Communitoria`;
- не ломает текущую навигацию и layout;
- добавляет связи и визуальные сценарии поверх уже существующих сущностей.
