# EDUMED v0.1: GENERAL DESCRIPTION

Ниже версия документа «EDUMED v0.1: GENERAL DESCRIPTION» с учётом всех уточнений, включая дневник.

## 1. Общая концепция экосистемы

Edumed — это школьная экосистема, а не одиночный электронный журнал. Система соединяет в одном пространстве работу администрации и педагогов с повседневной жизнью ученика и родителя: расписание, журнал, дневник, календарь событий, методические материалы, аналитику и коммуникацию.

### Ключевые идеи

**Ролевые кабинеты (offices)**  
У каждой роли есть свой кабинет — набор разделов и прав, через который пользователь взаимодействует со школой. Основные кабинеты:

- база сотрудников: директор, завуч, преподаватель;
- база клиентов: родитель, ученик.

Дополнительные роли («родитель», «преподаватель») добавляют свои кабинеты/разделы к основной роли.

**«Панельная вилка»**  
Если у пользователя есть несколько сущностей одного типа (несколько классов, детей, журналов), система сначала показывает панели выбора (карточки), а не случайный объект. Пример: преподавателю в разделе «Журнал» показываются панели «Класс + предмет», родителю в «Дневнике» — панели с детьми.

**Единое учебное пространство**  
Журнал, расписание, календарь и методическое пространство связаны:

- расписание задаёт структуру уроков по датам и времени;
- журнал автоматически подстраивается под расписание (даты и количество уроков);
- календарь с событиями временно «выбивает» уроки из расписания и журнала или возвращает их при отмене;
- методическое пространство связывает дисциплины, материалы и правила оценивания.

**Чёткие кодовые связи**  
Основные учебные сущности кодируются однозначно:

- дисциплины: `MATEM5`, `BIOLO7` и т.п.;
- ученики: `student<username><grade><group>`.

Это обеспечивает прозрачную привязку между пользователями, классами, группами и предметами.

## 2. Архитектура и принципы кода

### 2.1. Общий технологический стек

- **Клиент:** SPA на React + TypeScript, Tailwind-стили.
- **Сервер:** модульный backend с отдельными модулями для аутентификации, пользователей, классов, расписания, календаря, журнала, документов, аналитики, администрирования и т.п.
- **Связь:** REST API, аутентификация через JWT, авторизация по ролям.

Условно выделяются три слоя:

- **UI-слой (презентация):** компоненты страниц (`DashboardPage`, `JournalPage`, `SchedulePage`, `DiaryPage` и т.д.) и layout-компоненты (`AppLayout`, `PageContainer`).
- **Слой бизнес-логики:** правила ролей и кабинетов, «панельная вилка», кодирование дисциплин и учеников, диапазоны оценок и связи между журналом, расписанием, календарём, методическим пространством.
- **Слой данных:** сущности: пользователи, роли, классы, группы, ученики, дисциплины, расписание, события, оценки, документы, сообщения и т.п. Коды (`MATEM5`, `studentdillova51`) используются как стабильные ключи для привязки.

### 2.2. Роли, регистрация и кабинеты

При регистрации пользователь получает:

- фамилия (`lastName`);
- имя (`firstName`);
- отчество (`patronymic`);
- логин (`username`, минимум 5 символов, уникален);
- пароль (`password`);
- основная роль (`role`).

**Основные роли:**

- директор (`director`);
- завуч (`head_teacher`);
- преподаватель (`teacher`);
- родитель (`parent`);
- ученик (`student`).

**Добавочные роли:**

- преподаватель (`teacher`);
- родитель (`parent`).

**Правила:**

- основная роль не может быть добавочной одновременно;
- добавочная роль может быть основной в другом контексте (типы совпадают, но статус разный);
- добавочных ролей может быть несколько, их число не ограничено;
- изменение и добавление ролей после регистрации выполняется только из кабинета администратора.

Кабинеты (offices), с точки зрения кода, — это наборы разделов, привязанные к роли. Разделы можно добавлять, удалять, переносить между кабинетами без ломки общей архитектуры.

**База сотрудников** (`director`, `head_teacher`, `teacher`) — разделы:

- Главная (`main`).
- Аналитика школы (`analytics`).
- Документы (`document_archive`).
- Журнал (`journal`).
- Расписание (`timetable`).
- Методическое пространство (`methospace`).
- Чаты (`chats`).

**База клиентов** (`parent`, `student`) — разделы:

- Главная (`main`).
- Дневник (`diary`).
- Чаты (`chats`).

**Добавочные роли**

- добавочная роль «родитель» добавляет раздел Дневник;
- добавочная роль «преподаватель» добавляет разделы Журнал, Методическое пространство и Аналитика школы.

### 2.3. Принцип «панельной вилки»

**UX-правило:**  
Если у пользователя есть несколько сущностей одного типа (классы, дети, журналы и т.п.), при входе в раздел система показывает панели выбора, а не сразу первый элемент.

Панель представляет конкретную связку, например:

- «5 класс — Математика» (для журнала учителя);
- «Иванов Пётр» (для дневника родителя);
- «Кафедра естественных наук» (для методических материалов, если будет).

Клик по панели всегда открывает экран взаимодействия с этой сущностью (конкретный журнал, конкретный дневник и т.п.).

### 2.4. Кодирование сущностей

**Дисциплины:**  
Название → первые 5 букв → латиница → код (например, «МАТЕМАТИКА» → `MATEM`).  
Для каждого класса создаётся отдельная сущность: `MATEM1`, `MATEM5`, `MATEM7`.  
Учитель при выборе видит человеческое название («Математика»), а система опирается на код.

**Ученики:**  
`student<username><grade><group>`

- `username` — логин ученика;
- `grade` — номер класса;
- `group` — номер группы в этом классе.

Пример: логин `dillova`, класс 5, группа 1 → `studentdillova51`.  
Конец строки однозначно показывает, к какому классу и группе относится ученик.

## 3. Экраны и пользовательские сценарии

### 3.1. Главная (`main`) кабинетов

Видят: все роли (с разным наполнением).

**Общие элементы:**

- Приветствие: «Доброго времени суток, @username!».
- Панель «Календарь» с текущим месяцем: текущая дата обведена тонкой фиолетовой линией.
- Индикаторы времени: до обеда; до конца рабочего дня (для сотрудников).
- Список задач на день (локальные пользовательские задачи).

**Примеры:**

- Учитель: видит приветствие, календарь, таймеры, задачи; переходит в «Журнал» или «Расписание».
- Родитель: видит приветствие, уведомления (непрочитанные сообщения, будущие события), панели перехода в «Дневник» и «Чаты».

### 3.2. Календарь и расписание

**Календарь** — общая визуальная сетка:

- текущий месяц, даты над светлыми кружками;
- выделения: выходные и каникулы — светло-жёлтые; рабочие дни — светло-синие; мероприятия — светло-зелёные.

**Событие в календаре:**

- не создаёт отдельной учебной сущности, а управляет расписанием и журналом:
  - временно заменяет уроки в расписании;
  - временно «выбивает» урок из журнала.
- После прохождения: событие продолжает подсвечиваться зелёным;
- при изменении статуса на «несостоявшееся»: уроки возвращаются в расписание и журнал.

**Расписание (`timetable`)**

Экран:

- таблица: слева — временные слоты уроков, справа — колонки классов;
- под таблицей — настройка «время 1 урока = X минут»: изменение X меняет длительность всех слотов; отдельные слоты можно переопределять индивидуально.

**Создание связей:**

- Завуч создаёт классы (без букв, по номерам: 1–7 и т.д.).
- Класс может делиться на группы (например, 51, 52).
- При регистрации учителя указывается, ведёт ли он весь класс или конкретную группу.
- В расписании на одну ячейку может быть добавлено два урока, если они для разных групп одного класса.

**Связь с журналом:**  
По заполненному расписанию автоматически формируются колонки дат уроков в журнале для соответствующей дисциплины и класса.

### 3.3. Журнал (Journal)

**Выбор журнала (панельная вилка)**

- Преподаватель открывает раздел «Журнал».
- Система подтягивает все связки «класс + дисциплина», закреплённые за ним.
- На экране отображаются панели: «5 класс — Математика», «7 класс — Биология» и т.п.
- Клик по панели открывает журнал конкретного класса и предмета.

**Структура журнала**

- Левая колонка: список учеников (ФИО), по одному ученику в строке.
- Справа: колонки дат уроков, одна колонка = один урок.
- В самой правой части: колонка со средним баллом по предмету для каждого ученика.
- При наведении на дату в заголовке колонки открывается push-меню: тема урока; прикреплённые документы; количество присутствующих; средний балл за урок по классу (рассчитывается на основе оценок и отметки отсутствующих).

**Учитель:** выставляет оценки в ячейках; отмечает отсутствующих; может прикреплять материалы и видеть, какие методические пакеты привязаны к уроку (в связке с методическим пространством).

**Диапазоны оценок**

В методическом пространстве завуч:

- задаёт диапазоны средних баллов для итоговых оценок (1–5), например: «4» — от 3.8 до 4.69; «5» — от 4.7 до 5.0;
- по умолчанию все значения — 0;
- данные сохраняются только после явного сохранения завучем.

Журнал использует эти диапазоны для расчёта четвертных и годовых оценок.

### 3.4. Дневник (Diary)

Дневник — «зеркало журнала и расписания» для ученика и родителя.

**Для родителя (панельная вилка по детям)**

- Родитель открывает раздел «Дневник».
- Если у него несколько детей, видит панели по каждому ребёнку.
- После выбора ребёнка открывается дневник этого ученика.

**Структура дневника**

Для выбранного ученика:

- По каждому дню показывается список предметов, которые стоят в расписании на этот день.
- Напротив предмета — оценка(и), выставленные за уроки этого дня по этому предмету.

**Особенности:**  
В один день по одному предмету может быть два урока (например, две математики). Тогда:

- в журнале создаются две колонки с одинаковой датой, по одной на каждый урок;
- в дневнике у этого дня/предмета отображаются две оценки (либо две отдельные позиции), чтобы родитель и ученик видели оба результата.

**Связки:**

- Расписание задаёт, какие уроки должны быть в каждый день.
- Журнал хранит оценки по каждому слоту урока.
- Дневник агрегирует: «день → список предметов → оценки из журнала по слоту этого дня».

### 3.5. Методическое пространство (Methospace)

Роль: «рабочая библиотека и конструктор практик» для завуча и преподавателей.

**Основные блоки:**

- **Библиотека дисциплин:** список дисциплин с кодами (`MATEM5` и т.п.); карточка дисциплины: название, список классов, прикреплённые документы, диапазоны оценок, привязанные методические материалы.
- **Методические пакеты:** наборы материалов по темам: цели, план урока, материалы, домашние задания, критерии оценивания; пакеты можно привязывать к дисциплинам, классам и конкретным датам уроков.
- **Обратная связь по урокам:** завуч видит статистику по дисциплине/классу/учителю и может оставлять методические комментарии; учитель видит историю собственных уроков и связанные с ними материалы.

**Роли:**

- завуч: полные права на создание и редактирование дисциплин, диапазонов и материалов;
- преподаватель: просмотр своих дисциплин, создание/предложение материалов в рамках своих предметов;
- директор: обзор доступности методического обеспечения.

### 3.6. Аналитика (Analytics)

Назначение: «панель управления школой».

**Основные направления:**

- **Успеваемость:** средние баллы по школе, параллелям, классам, дисциплинам; распределение оценок; выявление «зон риска» (ниже порогов завуча).
- **Посещаемость:** проценты посещаемости по школе/классам/предметам; динамика по периодам; связь с мероприятиями из календаря.
- **Нагрузка и расписание:** количество уроков по дисциплинам и на каждого учителя; перегрузка и «окна».
- **Индивидуальные профили:** для ученика — графики по предметам и четвертям; для учителя — результаты по его предметам и классам.

**Ролевой доступ:**

- директор — полный обзор;
- завуч — по своим зонам ответственности;
- преподаватель — только свои классы и предметы;
- родитель/ученик — минимум (по себе), возможно в виде расширенного дневника.

### 3.7. Документы (Document archive)

Хранилище файлов с иерархией и тегами:

- папки уровня школы (приказы, локальные акты, общие методички);
- папки кабинетов и дисциплин (рабочие программы, раздаточные материалы, отчёты);
- документы используются по ссылкам во всех разделах — журнал, методическое пространство, аналитика.

**Важные моменты:** доступ и права (кто может загружать, удалять, редактировать); теги по дисциплинам, классам, ролям, периодам.

### 3.8. Чаты (Chats)

Коммуникация внутри школы:

- слева — список чатов и контактов;
- справа — активный диалог;
- сообщения доставляются мгновенно, есть уведомления о непрочитанных;
- на главной отображается счётчик непрочитанных сообщений.

### 3.9. Rivi

`Rivi` — визуальное пространство внутри EDUMED для проектных карт, маршрутов, группировки материалов и связи между документами, чатами и смысловыми блоками.

Ключевые принципы:

- работает как дополнительный режим внутри текущего layout EDUMED;
- не создаёт отдельную систему ролей и прав;
- использует существующие сущности `Документов` и `Чатов`, а не дублирует их;
- даёт пользователю бесконечное поле для визуальной организации содержимого.

Базовый сценарий:

- пользователь открывает раздел `Rivi`;
- видит галерею пространств в формате карточек;
- выбирает пространство и переходит в полноэкранное поле;
- основной интерфейс EDUMED сворачивается в компактный элемент возврата;
- на поле можно размещать текстовые блоки, фигуры, связи, документы и объекты групп/чатов;
- состояние поля сохраняется при выходе и возврате.

Интеграции:

- `Документы`: карточка документа размещается на поле и ведёт в исходный раздел или предпросмотр;
- `Communitoria`: группы могут быть привязаны к пространствам Rivi и открываться в split-режиме рядом с полем.
