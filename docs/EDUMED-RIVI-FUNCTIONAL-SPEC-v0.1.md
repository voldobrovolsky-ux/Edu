# EDUMED v0.1: RIVI FUNCTIONAL SPEC

## 1. Назначение

`Rivi` — визуальный режим работы внутри EDUMED для проектирования, обсуждения и навигации по связанным сущностям школы и команды: текстам, документам, маршрутам, группам Communitoria и смысловым кластерам.

Rivi не заменяет существующие разделы EDUMED, а дополняет их:

- использует уже существующие роли и права;
- связывается с `Документами` и `Communitoria`;
- работает как отдельный визуальный режим без потери контекста основного интерфейса.

## 2. Продуктовая идея

Rivi должно восприниматься как:

- свободное бесконечное поле, как в Canva/Figma;
- с простыми инструментами рисования, как в Paint;
- с возможностью собирать на одном холсте документы, обсуждения, идеи, этапы и связи между ними.

Ключевое UX-ощущение:

- жидкость;
- прозрачность;
- современная визуальная среда;
- минимум ощущения "формы" и "таблицы".

## 3. Экран входа: галерея пространств

### 3.1. Точка входа

- В левом меню EDUMED доступен раздел `Rivi`.
- При входе открывается галерея пространств Rivi.

### 3.2. Карточка пространства

Каждая карточка показывает минимум:

- название пространства;
- краткое описание;
- владельца или ответственного;
- статус (`В работе`, `Архив`, при необходимости дополнительные статусы);
- опционально теги.

### 3.3. Действия в галерее

Пользователь может:

- открыть существующее пространство;
- создать новое пространство;
- искать пространства по названию;
- фильтровать пространства по владельцу, статусу и тегам;
- сортировать пространства по дате изменения, названию или владельцу.

## 4. Переход в пространство

### 4.1. Сворачивание EDUMED

При открытии пространства:

- основной левый сайдбар EDUMED сворачивается в маленький круглый полупрозрачный элемент в левом верхнем углу;
- этот элемент всегда остаётся кликабельным;
- по клику пользователь возвращается назад, не теряя состояние пространства.

### 4.2. Рабочее поле

Остальная часть окна превращается в бесконечное поле:

- поддерживается pan;
- поддерживается zoom;
- допускается лёгкая сетка или точечный паттерн;
- нет жёсткой табличной структуры.

## 5. Объекты на поле

### 5.1. Текстовые и фигурные блоки

Пользователь может создать блок:

- с заголовком;
- с описанием;
- с цветом фона;
- с цветом границы;
- с уровнем прозрачности;
- с базовым стилем текста.

### 5.2. Рисование и фигуры

Доступны инструменты:

- ручка/маркер для свободного рисования;
- прямоугольник;
- круг/овал;
- линия;
- стрелка;
- ластик.

### 5.3. Документы

На поле можно добавить карточку документа из EDUMED:

- карточка отображает минимум название, тип и краткую метаинформацию;
- по клику открывается предпросмотр или переход в раздел `Документы`;
- карточка документа участвует в кластерах и связях как полноценный объект.

### 5.4. Связи и маршруты

Любые совместимые объекты можно соединять линиями/стрелками:

- через отдельный инструмент связи или режим "связать";
- с выбором типа линии;
- с изменением цвета;
- с возможностью добавить подпись;
- с возможностью редактировать форму связи.

### 5.5. Кластеры

Пользователь может:

- выделить несколько объектов;
- объединить их в кластер;
- задать имя, цвет и тег кластера;
- свернуть или развернуть кластер.

Кластер нужен для смысловой группировки, а не для изменения базовой модели объектов EDUMED.

### 5.6. Объект группы/чата

Если группа Communitoria привязана к пространству, на поле появляется объект `Группа/чат`.

Такой объект:

- можно перемещать;
- можно соединять с другими объектами;
- можно включать в кластер;
- можно открыть в split-режиме с чатом.

## 6. Общие действия с объектами

Для объектов на поле доступны:

- выделение;
- множественное выделение;
- drag-and-drop;
- изменение размеров там, где это допустимо;
- дублирование;
- удаление;
- изменение визуальных свойств;
- перемещение между смысловыми зонами поля.

## 7. Панель инструментов

### 7.1. Поведение

Панель инструментов:

- плавающая;
- перетаскиваемая;
- может магнитно прилипать к краям окна;
- не должна перекрывать критические элементы поля надолго.

### 7.2. Настройка панели

Через модальное окно пользователь может:

- выбрать набор видимых инструментов;
- изменить порядок кнопок;
- сохранить свой вариант панели для следующего входа.

### 7.3. Минимальный набор инструментов

- курсор/выбор;
- текст;
- фигуры;
- рисование;
- ластик;
- документ;
- кластер/группа;
- связь.

## 8. Навигация по полю

### 8.1. Перемещение

Поле перемещается:

- drag по пустому месту;
- либо через модификатор вида `Space + drag`.

Ожидание по UX:

- плавность;
- инерционность;
- отсутствие резких рывков.

### 8.2. Масштабирование

Zoom доступен:

- колесом мыши с модификатором;
- экранными кнопками `+` и `-`;
- через команду "сбросить вид" к базовому масштабу.

Zoom ограничивается минимальным и максимальным порогами для сохранения читаемости и производительности.

## 9. Интеграция с Communitoria

### 9.1. Привязка группы к пространству

В интерфейсе групп Communitoria появляется действие `Добавить в пространство Rivi`.

Пользователь:

- видит список доступных пространств;
- выбирает одно или несколько пространств;
- подтверждает привязку.

После этого в Rivi появляется объект группы/чата.

### 9.2. Открытие чата из Rivi

При открытии чата из объекта на поле:

- экран делится в пропорции примерно `20/80`;
- слева отображается чат;
- справа остаётся поле Rivi;
- после закрытия чата поле снова занимает 100% ширины.

### 9.3. Ограничения чата в режиме Rivi

В режиме чата из Rivi доступны:

- отправка сообщений;
- просмотр истории;
- базовое общение.

Не доступны:

- настройка прав группы;
- изменение структуры группы;
- административное управление сообществом.

Визуально чат из Rivi отличается:

- сообщения выравниваются вправо;
- аватары отправителей тоже находятся справа.

## 10. Стиль и визуальный язык

Rivi должен использовать:

- полупрозрачные панели;
- лёгкие градиенты;
- мягкий blur;
- аккуратные тени;
- спокойные, но живые цвета;
- чистое светлое поле.

Ключевые анимации:

- сворачивание сайдбара в круглый элемент;
- плавное появление инструментальной панели;
- мягкие переходы при pan/zoom;
- корректное сворачивание и раскрытие кластеров.

## 11. UX-ограничения

- Rivi ощущается как отдельный режим, но не разрывает связь с EDUMED.
- Возврат в основную систему должен быть быстрым и очевидным.
- Состояние пространства при возврате сохраняется:
  - положение камеры;
  - масштаб;
  - размещение объектов;
  - состояние раскрытых/свернутых кластеров.

## 12. Права доступа

Rivi использует существующую модель ролей и прав EDUMED.

Минимально достаточно двух уровней:

- `просмотр` — пользователь видит пространство и может открывать связанные сущности;
- `редактирование` — пользователь может создавать, удалять и изменять объекты пространства.

Отдельная новая ролевая архитектура для Rivi не вводится.

## 13. Неочевидные, но обязательные функции

Для полноценного UX Rivi должны быть предусмотрены следующие функции, даже если они не являются центральными сценариями:

- автосохранение состояния пространства без явной кнопки после большинства действий;
- ручная команда `Отменить/Повторить`;
- быстрый поиск объектов внутри текущего пространства;
- миникарта или обзор навигации по очень большому холсту;
- блокировка объекта от случайного сдвига;
- упорядочивание по слоям (`на передний план`, `назад`);
- базовые подсказки и пустые состояния для первого входа;
- сохранение пользовательских настроек панели инструментов;
- визуальная индикация несохранённых локальных изменений, если автосохранение временно не удалось;
- безопасное поведение при потере связи, чтобы пользователь не терял размещённые объекты;
- подтверждение удаления для крупных объектов или кластеров;
- режим только просмотра для пользователей без прав редактирования;
- запоминание последнего открытого пространства или последних недавно открытых пространств.

## 14. Критерии готовности

Rivi считается функционально готовым, если:

- пользователь видит галерею пространств;
- может создать и открыть пространство;
- получает бесконечное поле с pan/zoom;
- может работать с текстами, фигурами, рисунком, документами, связями и кластерами;
- может прикрепить группу Communitoria к пространству;
- может открыть чат в split-режиме;
- сохраняет состояние поля при возврате;
- не сталкивается с конфликтом существующих ролей и разделов EDUMED.
